# Архитектура STREETSPOT

## Технологический набор

Основной язык — Kotlin. Приложение состоит из одного Android-модуля. UI строится на Jetpack Compose и Material 3, навигация — Navigation Compose, локальная БД — Room, настройки — DataStore, асинхронные операции — Coroutines и Flow, виджеты — Jetpack Glance. Для камеры используется CameraX; существующие изображения выбираются Android Photo Picker. В базовой версии сеть не нужна; Firebase Authentication и Cloud Firestore обслуживают добровольный социальный этап 11, а Supabase Storage — выбранные пользователем фото.

Этап 0 не фиксирует номера версий. На этапе 1 были выбраны совместимые версии базового Android-стека. Для начатой реализации этапа 11 по официальной документации Firebase на 29.10.2026 выбраны Firebase Android BoM `35.1.0` и Google Services Gradle plugin `4.5.0`; Google Services plugin применяется только при наличии `app/google-services.json`. Сетевой доступ нужен только вошедшему пользователю для явных социальных действий.

## Структура

Предпочтительные пакеты одного модуля:

- ui/theme — цветовые схемы и типографика.
- ui/components — повторно используемые компоненты.
- ui/screens — экраны и их ViewModel.
- data/local — Room database, DAO и миграции.
- data/model — сущности и локальные модели.
- data/repository — чтение и изменение данных.
- data/photo — импорт, сжатие и удаление фотографий.
- data/preferences — DataStore.
- data/social — локальные настройки видимости и модели опубликованной сводки.
- data/remote — Firebase Auth, Firestore, Supabase photo endpoint и их узкие источники данных/репозитории.
- domain — XP, уровни и проверка достижений.
- widget — Glance widgets и обновление.
- navigation — маршруты приложения.

Названия пакетов и файлов уточняются с реальной структурой проекта. Не создавай отдельные Gradle-модули и универсальные framework-слои.

## Поток данных

Compose-экран наблюдает за состоянием своего ViewModel. ViewModel вызывает Repository, Repository использует Room DAO, PhotoStorage и DataStore. DAO выдаёт Flow для изменяемых коллекций и сводок. Правила XP и достижений находятся в небольших независимых domain-компонентах и не помещаются в экранные composable-функции.

Запись Spot, пересчёт транзакций XP и состояния достижений должны быть согласованы в транзакции Room. Доступ к файлам изображения вынесен в PhotoStorage. Виджеты получают согласованные сводки из локального хранилища и обновляются по факту успешных изменений; постоянный фоновый сервис не запускается.

В социальном этапе локальное изменение завершается независимо от сети. Для вошедшего пользователя Social Repository после локальной транзакции обновляет только разрешённую профильную проекцию в Firestore. Сетевая ошибка не откатывает Spot и не блокирует Home/Spotdex. Пользователь отдельно публикует выбранное фото; подготовленная копия без GPS EXIF передаётся в закрытый Supabase Storage через Edge Function. Функция проверяет Firebase ID token и право друга прочитать метаданные через Firestore Security Rules, затем отдаёт фото без постоянной публичной ссылки. На другом устройстве доступны профиль и опубликованные данные, но полный журнал Room не переносится.

Постоянная фоновая синхронизация всей базы и новый Android-модуль не требуются. Для первой реализации не добавлять общие абстракции или Firebase Cloud Functions; фото обслуживает один Supabase Edge Function. Обязательные правила безопасности и полное удаление аккаунта должны быть проверены до выпуска.

## Интеграция Firebase (план этапа 11)

- Firebase Authentication управляет текущим аккаунтом и входом email/пароль; Google Sign-In через Credential Manager рассматривается как дополнительный провайдер. Гостевой режим не создаёт анонимную облачную учётную запись.
- Cloud Firestore хранит небольшой снимок профиля и социальные отношения; его локальный кэш используется только для ранее загруженных данных и не заменяет Room.
- Закрытый бакет Supabase Storage `shared-spot-photos` хранит только выбранные для друзей фото. В Firestore остаётся метадата публикации.
- Firestore Security Rules закрыты по умолчанию. Edge Function проверяет Firebase ID token, а Firestore Rules подтверждают публикацию, принятую дружбу и отсутствие блокировки перед отдачей фото. Service key находится только в окружении Edge Function; прямых клиентских Storage policies и публичных ссылок нет.
- Случайный код STREETSPOT используется для точечного добавления; email и общий каталог пользователей не публикуются. Формат кода и правила запросов зафиксировать до реализации.
- Firestore Rules проверять через Local Emulator Suite на разрешённых и запрещённых ролях. Edge Function отдельно проверять с тестовыми Firebase и Supabase проектами. App Check — дополнительный слой, не замена Rules.
- Публичный XP — справочный клиентский снимок, не доверенная соревновательная величина. Лидерборды запрещены до появления серверной проверки.
- Firebase app config не является секретом доступа. Service-account credentials и Admin SDK ключи никогда не встраиваются в APK.

Полная согласованная модель, пользовательские решения, безопасность, стоимость, критерии и официальные ссылки находятся в [`docs/social-and-firebase.md`](social-and-firebase.md).

## Модель данных

Локальная схема Room обновлена до версии 3: миграция 1→2 добавляет nullable-поля года выпуска и типа кузова к Spot, миграция 2→3 — nullable-метаданные VehiclesDB к Brand и CarModel. Обе миграции сохраняют существующие данные.

### Brand

- id: стабильный локальный идентификатор.
- name: отображаемое имя.
- normalizedName: нормализованное имя с уникальным индексом.
- source: DEFAULT или USER.
- createdAt.
- vehiclesDbId: nullable-идентификатор марки VehiclesDB.
- aliases: альтернативные названия в локальном списковом представлении для поиска.

Нормализация убирает пробелы по краям, сводит повторные пробелы и сравнивает без учёта регистра; отображаемое написание сохраняется.

### CarModel

- id.
- brandId: внешний ключ Brand.
- name и normalizedName.
- generation и normalizedGeneration; пустая строка означает, что поколение не указано.
- countryCode: необязательная страна происхождения модели.
- category: одно значение JDM, EURO, MUSCLE, SUPERCAR, CLASSIC или OTHER.
- rarity: COMMON, UNCOMMON, SPORT, RARE или LEGENDARY.
- source: DEFAULT или USER.
- createdAt / updatedAt.
- vehiclesDbId: nullable-стабильный ID модели VehiclesDB.
- aliases и bodyTypes: локальные списковые представления альтернативных имён и типов кузова из источника.
- globalPopularityDecile / massPopularityDecile: nullable-группы 1–10, используемые только для порядка подсказок.

Уникальность модели: brandId + normalizedName + normalizedGeneration. Повторные встречи не создают CarModel. Каталоговые модели могут иметь редкость выше COMMON; пользовательская модель получает COMMON, это значение нельзя повысить из интерфейса. Для собственных моделей допускаются категория и страна без редкости выше базовой. Семенные данные добавляются идемпотентно и не затирают пользовательские записи.

При первом запуске приложение читает сжатый `app/src/main/assets/vehiclesdb/catalog-v2026.10.4.json.gz` и транзакционно объединяет записи с локальными марками/моделями по нормализованному имени. Стабильные внешние ID позволяют повторять импорт без дублей. Новые внешние модели получают OTHER и COMMON; децили VehiclesDB не влияют на XP или редкость. Год и поколения не импортируются.

Категория JDM/EURO/MUSCLE/SUPERCAR/CLASSIC/OTHER и поколение описывают выбранную модель и показываются при выборе; категория задаётся при создании пользовательской модели.

### Spot

- id.
- carModelId: внешний ключ CarModel.
- photoPath: относительный путь к копии во внутренней папке приложения.
- photoSha256: SHA-256 сохранённой нормализованной копии для обнаружения точной повторной загрузки.
- observedAt: момент находки для сортировки и определения времени.
- observedLocalDate: календарная дата ISO, сохранённая при добавлении; не меняется при смене часового пояса.
- observedLocalTime: локальное время HH:mm, сохранённое при добавлении; используется для ночных достижений и не меняется при смене часового пояса.
- createdAt: время сохранения записи.
- color и notes: необязательные строки.
- placeLabel: необязательная введённая пользователем подпись места без GPS-координат.
- vehicleYear: необязательный год выпуска конкретного замеченного автомобиля.
- bodyStyle: необязательный тип кузова конкретного замеченного автомобиля: седан, хэтчбек, купе, универсал, лифтбек, внедорожник, кроссовер, пикап, фургон, родстер, кабриолет, минивэн или другой. Для VehiclesDB модели список предлагаемых типов ограничивается данными источника.

Одна Spot — одна запись наблюдения; у одного CarModel может быть много Spot. Точное совпадение модели, локальной даты и SHA-256 показывается как возможный дубль и предлагает открыть существующую запись. Если пользователь подтверждает отдельную находку, XP по этому совпадающему фото не начисляется. Другие записи остаются в дневнике; защитить от намеренного повторного ввода того же автомобиля без номера, геопозиции или распознавания нельзя, поэтому повторный XP также ограничен правилами из docs/xp-and-achievements.md.

Удаление CarModel с привязанными Spot запрещено. Пользовательскую модель без находок можно удалить. Удаление Spot каскадно удаляет её XPTransaction, но не каталоговую модель.

### XPTransaction

- id.
- spotId: внешний ключ Spot с удалением каскадом.
- amount: положительное число XP.
- reason: BASE_RARITY, NEW_MODEL, NEW_BRAND или REPEAT_SPOT.
- createdAt.
- уникальный ключ (spotId, reason), чтобы одна причина не начислялась одной записи повторно.

Строки транзакций — производный журнал, пересобираемый из текущих Spot-записей после изменения влияющих на XP полей. Текущий XP — сумма журнала, а не независимый изменяемый счётчик.

### AchievementState

- achievementId.
- unlockedAt: nullable timestamp.

Список определений и порогов достижений фиксирован в domain-коде; прогресс рассчитывается по Spot и CarModel. Эта таблица нужна для состояния уведомления/фиксации текущей разблокировки, но не является источником статистики. Достижения не выдают XP.

## XP, редкость и достижение согласованности

Полные формулы, пороги 30 уровней, правила одинаковых дат, повторных моделей, достижений и пересчёта находятся в docs/xp-and-achievements.md. XpCalculator и AchievementChecker — небольшие доменные компоненты. Сортировка событий детерминирована: observedAt, затем createdAt, затем id. При добавлении, удалении или изменении модели/даты журнал и состояния достижений пересчитываются атомарно.

## Фото и приватность

Из Photo Picker нельзя сохранять временный URI как единственную ссылку: выбранное изображение копируется в приватную внутреннюю папку. CameraX сохраняет снимок в тот же управляемый путь. На импорте удаляются EXIF GPS-метаданные и готовится уменьшенная копия для просмотра; начальный ориентир — длинная сторона около 2048 px и JPEG quality около 88, с проверкой качества и памяти на этапе 4. Исходник не требуется хранить отдельно.

Файл готовится до фиксации ссылки в Room. При ошибке БД временный файл удаляется; при удалении записи фото удаляется после успешной транзакции, а ошибки удаления обрабатываются как очистка неиспользуемых файлов. В резервную копию входит согласованная копия базы и фото.

Геолокация автоматически не запрашивается. Если пользователь указывает место, хранится введённая подпись, не координаты. В базовой версии серверной передачи нет. В социальном этапе аккаунт и публикация необязательны; публичная проекция не содержит email, заметок, подписи места или полного списка Spot. Для облачного фото используется отдельная подготовленная копия без GPS EXIF, и только после выбора пользователем.

## Время и локальные сводки

Для каждой Spot сохраняются момент времени и снимки локальной даты и времени. Дата для лимита повторного XP и время для NIGHT RIDER берутся из этих полей, а не пересчитываются при последующей смене часового пояса. При редактировании даты пользователь сохраняет локальное время либо меняет его отдельно; момент observedAt синхронно обновляется. Ночная находка для NIGHT RIDER — время от 20:00 включительно до 06:00 невключительно. Текущий месяц в Stats вычисляется по календарю и текущему часовому поясу устройства.

## Настройки, резервная копия и виджеты

DataStore хранит выбор динамических цветов. Значение по умолчанию — выключено, Midnight JDM. Системное уменьшение движения читается из настроек Android, отдельная копия этого системного значения не хранится.

Пользовательский экспорт/импорт реализован через системный выбор файла: ZIP-архив с версионированным manifest, каталогом, Spot-записями, состояниями достижений и изображениями. Версия 2 включает год и тип кузова; версия 3 дополнительно включает VehiclesDB ID, псевдонимы, типы кузова и децили популярности. Версии 1 и 2 по-прежнему принимаются, отсутствующие новые поля восстанавливаются пустыми. При восстановлении архив и фотографии проверяются до транзакционной замены данных в Room; фотографии сначала копируются под новыми путями. Импорт источника каталога после восстановления заполняет отсутствующие метаданные. XP пересчитывается из правил текущей версии. Android Auto Backup отключён через `allowBackup=false`; extraction rules исключают cloud backup и device transfer, а legacy full-backup rules исключают данные на Android 11 и ниже. Пользователь сохраняет архив вручную. Архив не шифруется приложением и не включает настройку динамических цветов. Firebase-профиль и дружеские связи не входят в этот архив и не являются резервной копией дневника. Работу резервного копирования на устройствах не проверяли.

### Источник каталога автомобилей

- В приложение включён только тип `car` VehiclesDB v2026.10.4; сетевого клиента и фонового обновления каталога нет.
- Полные атрибуция и условия использования лежат в assets рядом с данными и доступны из Settings. Данные лицензированы CC BY 4.0; `ATTRIBUTION.md` содержит требуемое упоминание VehiclesDB и формулировки первичных реестров.
- Опубликованные страны: ar, au, ca, ch, de, es, fi, gb, ie, il, lu, my, nl, no, nz, th, ua, us. Эти источники не позволяют представлять показатель как популярность в России.
- Поколения, варианты и точные количества регистраций не используются. Децили — только сортировочные подсказки, категории STREETSPOT и XP остаются независимыми.
- Подробное описание версии и импорта: [`docs/vehicle-catalog.md`](vehicle-catalog.md).

Level Widget показывает уровень, ранг и XP-прогресс, нажатие открывает Home. Collection Widget показывает Total Spots, Brands Discovered и прирост текущего месяца, нажатие открывает Spotdex. Оба виджета примерно 2×2, используют Material You, если он включён, и обновляются после успешного изменения данных.
